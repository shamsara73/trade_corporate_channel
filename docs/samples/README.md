# Sample messages

One place for the messages exchanged between the channel (TCC) and Trade Innovation (TI), per product and event, in the order they travel:

| Step | File name starts with | What it is | Queue |
|---|---|---|---|
| 1 | `1-tcc-request-` | **TCC request**: the channel's `ServiceRequest` (Service `TI`) | TI's incoming queue |
| 2 | `2-ti-reply-` | **TI reply**: TI's immediate `ServiceResponse`, matched by `CorrelationId` = the request's `TheirRef` | the reply queue |
| 3 | `3-ti-response-` | **TI response**: the outward message (Service `GATEWAY`) sent when a trade service officer completes (`…ACK`) or refuses (`…REJ`) the event. Matched by `eBankMasterRef` + `eBankEventRef` | TI's outward queue (may be the reply queue) |

All customer data and references are **invented** (ground rule 9). In the bank's messages they were replaced; everything else is as received. The application's tests read these files directly, so they stay correct: a sample that no longer matches the code or its TI mapping fails the build.
