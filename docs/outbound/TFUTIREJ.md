## Points to check with the TI team

* **Same tag, same type, different field name:** . If these are meant to differ, the mapping gives them identical values. TI's list has no separate "transaction amount" for `TnxAmount`, but it does have `TAVE` = "Available amount after this event", which is probably what `AvailableAmt` should use instead of `OUA`.
* **Same field name twice:** `AttachedDocuments`, `Charges`. TI's list explains the two `Charges` tables: `AAOC` = "Addressee our charges" and `AABC` = "Addressee OB charges" (charges for the addressee: ours, and other banks'). `GDOCS` = "Gateway documents for addressee"; `tAATT` is a bank-defined tag that is **not** in the IGT issue event list. A consumer must tell them apart by tag.
* **Tags that are not in the IGT issue event field list:** `tAATT` (field `AttachedDocuments`). A tag outside the list cannot be filled for this event; `CMBYC` is probably meant to be `CMBY` ("Confirmed by").
* **Tag reused across types:** `DAD` is both a flag and a day count, and `DFRP` both an integer and a string. Treat tag **and** type as the key.
* **3 fields have only a low-confidence counterpart** (the renewal and reduction groups need a business check): `InstructingPartyRef`, `OurRequestTypeCodeSend`, `PrincipalID`.
