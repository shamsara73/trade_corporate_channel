## 1. Short answer

There is **no table of tags**. A tag such as `EXP-U`, `BEN` or `AMT-U` is a TI **event field code**, the same short code TI uses elsewhere for event fields. The mapping is a **template** whose placeholders name event fields; the data comes from the product tables, and the template itself is stored as a document template.

## 2. The notation is TI event-field notation

The second item of each tag is the **event field type**. The set of letters in the mapping is exactly the set in the database specification:

> `EFDEFNITEM.EVFLDTYPE`: Event field type a = Account - = Address v = Amount b = Branch y = Country z = Currency c = Customer d = Date i = Integer + = List l = Logical n = Narrative p = Party q = Party settlement r = Reference s = String f = System account * = Table g = Team t = Timestamp u = User x = Watch list checker party report m = Customer address

| Mapping item | Database column | Example in `TFUTICRT` |
|---|---|---|
| first item (`EXP-U`, `BEN`) | `EVFLDCODE` (string 10), `CRITERION.EVENTF98` (string 17) | `EXP-U`, `AMT-S`, `cAAU` |
| second item (`d`, `v`, `p`, `*`...) | `EVFLDTYPE` (string 1) | `d` date, `v` amount, `p` party, `*` table |
| third item (`g`, `u`, `c`, `cu`, `sw1`...) | `EVFLDPART` (string 10), `CRITERION.FIELDPART` (string 4) | `u`/`c` amount and currency, `cu`/`sw1` party parts |

This settles most of open question Q23. It does **not** explain the `-U` / `-S` suffixes, which are part of the event field code; their meaning comes from the column families in section 3.

## 3. Field by field

Columns come in three families in the guarantee tables (`ISSGTE`, `IGMASTER`, and the amendment tables `IGTNEWAMD` and `ORIGIGTAMD`): `UndertakingIssuedDetails.CounterReceived.*` (prefix `CR`), `…CounterToSend.*` (prefix `CS`) and `…ToSend.*` (prefix `LU`, plus `TOG*`). The mapping matches them: **`-U` fields are the `ToSend` family** (the full undertaking, including delivery, wording, transfer and underlying-transaction text, which carry no suffix in the mapping) and **`-S` fields are the `CounterToSend` family**, which lacks exactly those elements. There is no `-R` field for `CounterReceived`. This supports the reading in the README that `-S` is the counter-undertaking to send.

Where a column exists in both the event table (`ISSGTE`, the values of this event) and the master table (`IGMASTER`, the current values) both are listed.

## 4. Parties

Every party is a row of `PARTYDTLS` ("Party Details"), identified by its **role code** `PARTYDTLS.ROLE` (string 3), which matches the party tags in the mapping (`APP`, `BEN`, `ADV`, `THB`, `CIB`, `FIB`, `RQC`...). The role codes themselves are data in `PTY_ROL` (`PTYROLE_KY`, `DESCRIP`, `VAL_PCP`, `VAL_NPCP`); the specification does not list them. The party tag and the part (third item) select the column:

## 5. Status values the specification gives us

These answer part of open question Q3 and feed [ADR 0008](../architecture/decisions/0008-status-tracking.md).

| Column | Meaning |
|---|---|
| `MASTER.STATUS` | Status BKF = BKF CAN = CAN EXP = EXP LIV = LIV NEW = NEW PRV = PRV |
| `MASTER.PREV_STS` | previous status, same codes |
| `BASEEVENT.STATUS` | Status i = In progress c = Completed a = Aborted |
| `BASEEVENT.STATUS_EV` | Event specific status |
| `BASEEVENT.EVTREFUSED` / `EVTREFSTOR` | Event refused / Event refused reason |
| `BASEEVENT.EXTSTAT` | External review status C = Confirmed R = Rejected |
| `GWYIN.STATUS` (inbound message) | Status A = Active P = Processed F = Errors R = Rejected O = Requires action X = Re-processed |
| `GWYIN.ERRMSG` | Err msg U = Unable to find master D = Duplicate message E = Error in mapping R = Requires repair N = NAK'd |

So an event is *in progress*, *completed* or *aborted*; it can be *refused* with a reason; the master is `NEW`, `LIV` (live), `CAN`, `EXP`, `BKF` (booked off) or `PRV`. A message from the channel that cannot be processed is held in `GWYIN` with an error code (`U` unable to find master, `D` duplicate message, `E` error in mapping, `R` requires repair, `N` NAK) – which also answers part of Q7: **TI detects duplicate inbound messages** (`ERRMSG` = `D`), although the specification does not say on which key.

## 6. Tables and what is not located

* **Charges** (`Charges` tables, tags `AAOC` and `AABC`): `BASECHARGE`, one row per charge (`MASTER_KEY`, `EVENT_KEY`, `STATUS` `X` in preparation, `O` outstanding, `P` paid, `A` superseded, `W` waived…, `CHG_DUE`/`CHG_CCY`, `EXCH_RATE`, `VALUE_DAT`, `BILL_STS`). Why there are two tables is unknown (Q24).
* **Linked licences**: `LIC_LINK` (`LICENSE_NO`, `AUTH_REF`, `ALLOC_AMT`, `ALLOC_CCY`).
* **Irregular reduction schedule** (`IRSA-*`): `IRR_RED`.
* **Attached documents**: `DOC_ATTACH` links an event document, a gateway message (`ATT_GW_MSG` → `GWYIN`), mailing details or a SWIFT message; the DMS identifiers sit in the document tables.
* **Narratives** (`IIB`, `IAB`, `RTS`, `ADL`, `GDS`, `FFI`, `DCS`, `GSI`) and **accounts** (`CHA`, `PRA`), **goods and shipment** (`GDC`, `SDF`…, `PRSP`) and **contract details** (`GCRC`…): not found in `ISSGTE` or `IGMASTER`; they are in other event or master tables not matched by name here. Search with `python3 -I tools/dbspec/dbspec_lib.py search <text>`.
* **Computed values** (`TnxAmount`, `AvailableAmt`, `TFMD`, `SLN-U`): derived at message time.

## 7. Queries to confirm and to collect the other mappings

Run these in the TI test database (they are plain SQL and work on SQL Server and Oracle; `FETCH FIRST` needs SQL Server 2012+ / Oracle 12c+). They only read.

```sql
-- 1. Find the template that holds the TFUTICRT mapping
SELECT KEY97, DESCRI56, ADVMTH80, MSGSUBTYPE, FILENA69, DOCUME41, OBSOLETE
  FROM DOCUME59
 WHERE TEMPLA49 LIKE '%TFUTICRT%';

-- 2. See messages generated from it (newest first); DOCXML is the outward message as sent
SELECT o.KEY97, o.EVENT, o.DOCFORMAT, o.TFR_MTHD, o.LASTSAVD
  FROM OUTPUTDOC o
 WHERE o.DOC_TEMP = :template_key -- KEY97 from query 1
 ORDER BY o.LASTSAVD DESC
 FETCH FIRST 20 ROWS ONLY;

-- 3. Collect ALL gateway templates (the other outward mappings Q22 asks for)
SELECT KEY97, DESCRI56, MSGSUBTYPE, FILENA69, DOCUME41, TEMPLA49
  FROM DOCUME59
 WHERE ADVMTH80 = 'a';

-- 4. Which products / events use document templates, via the document type (DOC_TYPE has the type key)
SELECT t.KEY97, t.DESCRI56, t.DOCUME41
  FROM DOCUME59 t
 WHERE t.TEMPLA49 LIKE '%<<TEXT,T,%';

-- 5. Event-field code catalogue for the guarantee events (code, type, description)
SELECT DISTINCT REPFLDCODE, REPFLDTYPE, REFFLDDESC
  FROM REPEXTFLDS
 WHERE REPFLDCODE LIKE '%-U' OR REPFLDCODE LIKE '%-S';
```

Query 3 is the quickest way to get every outward mapping the bank has configured, without waiting for the TI team to send them one by one. Save each result as a file in `sources/ti_outbound/` (as received) and add it to the generator.
If query 1 returns nothing, the template is probably a Word or DMS-held template (`TEMPLT`, `TEMPLTVER` with `DMSID`) or lives in a file outside the database; ask the TI team where `TFUTICRT` is configured.
